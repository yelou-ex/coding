## 一、三层是什么关系（先看这张表）

| 层 | 代码位置 | 角色 | 模数 | 谁生成 |
|---|---|---|---|---|
| **LWE** | `coding/lwe-java/` | **输入**：加密的索引 / 行号 | **q_LWE = 2N**（结构约束） | 客户端 |
| **RLWE** | **`coding/rlwe-java/`**（独立模块，被 rgsw-lab 依赖） | **数据与累加器**：数据库列密文、累加器 | **q_R = 多个素数（NTT 友好）** | 客户端 |
| **RGSW** | `coding/rgsw-lab/` | **评估材料**：选择器、自举密钥 | 与 RLWE 同模数 q_R | 客户端（Setup 阶段） |

### ⚠️ 两个模数不同是**正常的**，不要试图统一

这是最容易搞混的一点，也是 TFHE 的标准结构：

```
客户端：用大模数 q_LWE 加密索引（保证安全性）
   ↓ 服务器做「模数切换」
盲旋转输入：q = 2N ← 只有 q = 2N，才能把 b 嵌进长度 2N 的旋转群（X^b）
   ↓ 服务器在累加器上做 d 轮 CMUX
累加器 / 评估材料：始终在 RLWE 的大模数 q_R 上
```

- **LWE 的 q = 2N**：因为盲旋转要把 `b` 编码成 `X^(−b)` 写进长度 2N 的累加器，索引按 `mod 2N` 取。
  论文（Pirouette §3.2）原话：*"we consider input LWE ciphertexts with modulus q = 2N"*。
- **RLWE 的 q_R**：论文用 SEAL 默认配置，实测 N=16384 时是 **9 个素数 / 438 位**；我们实验层用 15 个 31 位素数 / **451 位**。
- 两者由**模数切换**连接（`LWECiphertext.switchModulus`）。

## 三、LWE 层（`coding/lwe-java/`）

### 3.1 数学约定

```
密钥 s ∈ {0,1,2}^d  或  {0,1}^d（盲旋转必须用后者）
密文 (a, b)：a ← Z_q^d 均匀，b = ⟨a,s⟩ + Δ·m + e (mod q)，Δ = q/t
解密：phase = b − ⟨a,s⟩ → 中心化 → 除以 Δ 四舍五入 → 取模 t
```

### 3.2 参数

| 参数 | 值 | 来源 |
|---|---|---|
| 维度 d | 512 | Pirouette Table 4（**CAPE 未给出**；综述说 PIR 典型 512–4096） |
| 模数 q | 2^12 = 4096 = 2N（N=2^11） | Pirouette Table 4 |
| 明文模数 t | 16（ν=4） | Pirouette 未直接给出，按"每次盲旋转 4 位"推得 |
| σ | √3.192 ≈ 1.787 | Pirouette Table 4 |

**CAPE 对齐预设**（本轮新增）：

```java
LWEParams cape = LWEParams.forRingDimension(16384, 512, 4, 1.7866);
// → q = 2N = 32768, t = 2^4 = 16, Δ = 2048, 噪声预算 1024
```

> **t 不是自由参数**：`t = 2^ν`，ν 是"每次盲旋转能处理的位数"；索引位数 k 需要 **⌈k/ν⌉ 次盲旋转**。
> 例：行号范围 R ≤ N = 16384 → k = 14 位 → ν=4 时约 4 次、ν=5 时约 3 次。

### 3.3 本轮新增的能力

| API | 作用 |
|---|---|
| `LWE.keyGenBinary()` | 生成**二值**密钥 s ∈ {0,1}^d（CMUX 按位选择的硬要求） |
| `LWE.toBitArray(sk)` | 导出 `int[]`，直接喂给 RGSW 层的自举密钥生成 |
| `LWECiphertext.switchModulus(q')` | 模数切换（**已改为大整数精确舍入**，原来用 double 会丢精度） |
| `LWE.decryptSwitched(sk, ct)` | 解密切换后的密文（比例因子按新模数重算） |
| `LWE.switchNoiseBound(d)` | 切换噪声上界（最坏 d/2） |
| `LWEParams.forRingDimension(N, d, ν, σ)` | CAPE 对齐预设 q = 2N |

### 3.4 实测（`ModSwitchTest`，全部通过）

```
Test 1  二值密钥            200/200 解密正确，512 位全在 {0,1}
Test 2  模数切换 q→2N       200/200 正确，实测噪声 15（阈值 128）
Test 3  切换噪声 vs 维度：
           d=64   → 6        d=256  → 7        d=512  → 13
           d=1024 → 12       d=2048 → 23       阈值均为 128
Test 4  CAPE 预设           q = 2N = 32768, t = 16, Δ = 2048
```

**结论**：模数切换的噪声上界是 d/2，但舍入误差是**随机**的，实测只有 **√d/2** 量级。
所以 q=2N 下噪声远小于预算，**切换本身不是瓶颈**。

## 四、RLWE 层（`coding/rlwe-java/`，独立模块）
> 包名 `com.fusepir.rlwe`，零依赖，可打 `rlwe.jar`。`rgsw-lab` 依赖它（`run.ps1` 会一起编译）。
> **与 MPC4J 的优缺点对比**见 `rlwe-java/README.md` 第五节。

### 4.1 参数（可表达的部分全部按论文）

| 参数 | 取值 | 来源 |
|---|---|---|
| 明文模数 t | **65537** | ✅ 论文 §5.1 |
| 多项式次数 N | **16384** | ✅ 论文 §5.1 |
| 系数模数 q_R | **15 个 31 位素数 / 451 位** | ⚠️ 论文用 SEAL 默认（9 素数 / 438 位）；本实验到此规模 |
| gadget 基数 B | **2^16** | ⚠️ 论文未给；与 MPC4J 的 C++ 实现一致 |
| gadget 层数 l | 按 B^l > q 自动取（15 素数时为 29） | ⚠️ 同上 |
| 噪声 | 4 比特（σ≈1） | ⚠️ 论文未给，本实验自选 |

### 4.2 本轮改动（RLWE 层）

这一层本轮动得最多，因为它原先只能跑"玩具参数"。改动分三类：

#### (1) 模数规模：从"最多 2 个素数 / 62 位" → "任意素数个数 / 451 位"

| 项 | 改动前 | 改动后 |
|---|---|---|
| q 的表示 | `long`（≤ 62 位，最多 2 个素数） | `BigInteger`（任意个数；实测 15 素数 ≈ 451 位） |
| 跨素数还原（CRT） | 2 素数专用公式，用单个 64 位整数算完 | **增量式 CRT**：逐步合成，每一步的逆元**预计算**（`RingParams.crtStepInv`），避免热路径里做 `modInverse` |
| 素数生成 | 直接取固定常数 | 自动生成 **NTT 友好素数**（满足 2N \| p−1），从上一个素数之后继续找并**查重** |
| 编码 / 解码 / 相位 / 噪声 | `long` 运算 + double 取整 | 全部 `BigInteger`：编码 `round(m·q/t)`、解码 `round(相位·t/q)`、噪声上限 `q/(2t)` |

**为什么必须做**：论文的系数模数是 SEAL 默认配置，实测 N=16384 时是 **9 个素数 / 438 位**。
在 62 位模数下，gadget 基数 2¹⁶ 根本放不下（实测单素数下 base≥256 直接解密失败）。

#### (2) 速度：NTT 接入 + 三处"常驻 NTT 域"缓存

| 优化 | 说明 | 效果（N=16384） |
|---|---|---|
| **NTT 环乘法** | O(N²) → O(N log N)；参数生成时自动挑 NTT 友好素数，挑不到就自动回退朴素乘法 | 外部乘积 3.6 s → **0.054 s**（同配置） |
| **评估密钥常驻 NTT 域** | 同一份 RGSW 一次查询复用上千次且不变，首次用到的 NTT 结果缓存 | 外部乘积里变换次数从"每次 O(l) 次乘法"降到 2l+2 次 NTT |
| **私钥常驻 NTT 域** | 加解密与相位都要做"私钥 ⊛ 多项式"，私钥全程不变 | 加密 0.483 s → **0.037 s**（13×）；解密 0.143 → **0.024 s** |
| **小系数快路径** | 数字多项式 / 三元密钥的系数很小，内层可以整段累加后再取模 | 6.5×（数学完全不变） |
| **CRT 逆元预计算** | 跨素数还原每次外部乘积调用 2N 次 | 去掉热路径里的 `modInverse` / 查表 |

#### (3) 修掉的三个 bug（都不报错、只算错，或直接挂住）

| bug | 症状 | 根因 | 对策 |
|---|---|---|---|
| `BigInteger.longValue()` 有符号截断 | 15 素数时外部乘积**全错**，1~2 素数时正常 | q 有 451 位，`longValue()` 只取低 64 位**且带符号**；低字为负时选择器系数变成负数→被归约成 p−4 | 超 64 位的量一律用大整数取模 |
| 素数生成重复 | 报"逆元不存在"（CRT 直接崩） | 相邻偏移量会搜到同一个素数 | 从上一个素数之后继续找 + 构造时显式查重 |
| 素数候选向下对齐 | 又搜回上一个素数 | 对齐公式 `start − (start mod 2N) + 1` 会落到起点**之前** | 改为**向上**对齐到 ≡1 (mod 2N) |

#### (4) 配套：参数预设与可调项

```java
RingParams.lab()                    // 单素数、N=1024：快，用于迭代调试
RingParams.paperParams(16384, 15)   // t=65537、base=2^16、15 素数 ≈ 451 位
```

可调项全部走 `params.env`（`RGSW_N` / `RGSW_PRIMES` / `RGSW_PRIME_BITS` / `RGSW_BASE` / `RGSW_LEVELS` / `RGSW_NOISE_BITS` / `RGSW_TRIALS`），不用改 Java 代码。

### 4.5 MPC4J 的 RLWE 能力边界（2026-09-16 实测）

RLWE 层现在直接用 MPC4J（`coding/lib` 里的 SEAL 4.0.0 Java 移植）。CAPE 在 RLWE 层需要的
四件事**逐项跑过、逐项核对结果**（探针 `rgsw-lab/src/main/java/com/fusepir/rgsw/Mpc4jCapability.java`，
N=4096、t=65537、3 素数、q=109 位）：

| 能力 | 对应 CAPE 子程序 | 实测 | 数字 |
|---|---|---|---|
| 槽打包 `BatchEncoder` | Pack / 2-D 布局 | ✅ 4096 槽加解密往返 0 错位 | — |
| 密文×密文 + 重线性化 | CtCtMul | ✅ 逐槽乘积 0/4096 错位 | 85 ms + 25 ms，规模 3 → 2 |
| 槽旋转 `rotateRows` | CtRotate | ✅ 实测方向 = 槽下标 +1 | 14 ms（密钥生成 29 ms） |
| 模数切换 | LWE(q=2N) ↔ RLWE 的桥、响应压缩 | ✅ 切换后仍正确解密 | 3 → 2 素数 |

**三条硬边界，必须按它设计参数：**

1. **到不了论文的 N=16384 + 438 位**。MPC4J 的 `AbstractGaloisTool` **每层模数**分配 N² 个 int：
   N=16384、9 素数 ≈ 9 GB，必然 OOM。实测可用区间是 **N ≤ 8192 且素数 ≤ 3**
   （本次 N=4096 + 3 素数 ≈ 201 MB，正常）。
2. **噪声余量很浅，这才是真正的限制**（N=4096 / 109 位）：
   - 密文×密文之后只剩 **24 bit**；
   - 模数切换一次从 **51 → 12 bit**（掉约 39 bit，符合 log2(q/q′) 的预期）。
   所以 CAPE 的电路深度必须按这个预算设计——这也解释了为什么 CAPE 以**密文×明文**为主、
   只在必要处用 cmux（每次 cmux = 1 次外部乘积）。
3. **模数切换不能在 NTT 形式下做**：BFV + NTT 会直接抛
   `BFV encrypted cannot be in NTT form`，必须先在系数域再做。

**MPC4J 没有的（必须我们自己写，已在 `rgsw-lab`）**：RGSW.Enc、外部乘积/CMUX、BlindRotate、
SampleExtract，以及整层 LWE（`coding/lwe-java`）。MPC4J 的 FHE 只有 `mpc4j-crypto-fhe-seal`
一个模块（就是 SEAL 的移植），没有 TFHE / RGSW / LWE 实现。

## 五、RGSW 层（`coding/rgsw-lab/`）

### 5.1 核心 API

| API | 论文对应 | 作用 |
|---|---|---|
| `RgswOps.encrypt(p, key, μ, rnd)` | `RGSW.Enc` | 加密一个选择器比特 |
| `RgswOps.externalProduct(p, rgsw, ct)` | `ExternalProduct` | RGSW ⊗ RLWE → RLWE（CMUX 的核心） |
| `MonomialOps.mulMonomial(p, ct, k)` | —（盲旋转的旋转步） | **本轮新增**：把累加器乘上公开单项式 X^k |
| `BootstrapKey.generate(p, key, bits, rnd)` | Setup 的评估材料 | **本轮新增**：对 LWE 密钥每一位生成 RGSW |
| `BootstrapKey.describeBytes(p, d)` | — | **本轮新增**：自举密钥体积（可行性红线） |

### 5.2 公开单项式旋转的符号约定（容易错）

环是 Z_q[X]/(X^N+1)，即 X^N = −1：

```
先约化 k mod 2N：
  k < N  → 正常平移 k 位
  k ≥ N  → 等价于 −X^(k−N)：整体取负 + 平移 k−N 位
平移时 i+k ≥ N 的项，因跨越 X^N 也要变号
最终符号 = (是否整体取负) XOR (是否跨过 X^N)
```

实测：`k < N` 与 `k ≥ N` 两组共 9 个位移，逐位对照全部正确。

### 5.3 自举密钥体积 —— **可行性红线**

```
自举密钥 = d 个 RGSW，每个 RGSW = 2l 个 RLWE 密文，
每个 RLWE 密文 ≈ 2N 个系数 × ceil(qBits/8) 字节
```

| 场景 | d | l | 体积 |
|---|---|---|---|
| 实验参数（N=1024、q=31 位） | 512 | 16 | 128 MB |
| 实验参数 | 1024 | 16 | 256 MB |
| **论文规模（N=16384、q=451 位）** | **512** | **29** | **约 52 GB** |

**这就是"必须先把 d 和 l 定下来"的原因**：l 由 q 和 B 决定，d 由 LWE 参数决定，
两者一乘就是几十 GB 量级。降低办法：减小 d、增大 B（减少 l）、或在原型阶段用较小的模数。

## 七、踩坑清单（跨三层，全部实测踩过）

| # | 坑 | 症状 | 对策 |
|---|---|---|---|
| 1 | 编解码不互逆 | 消息接近 t 时整体偏移 | 编码 `round(m·q/t)`、解码 `round(相位·t/q)`，用真实比值 |
| 2 | 相位先中心化再解码 | m > t/2 时全线出错 | 相位按无符号解释，直接"乘 t 除 q 取整" |
| 3 | 切段不覆盖 q | 静默算错 | 强制检查 B^l > q |
| 4 | 三元密钥的 −1 存成 q−1 | 走"小系数快路径"会溢出 | 三元专用乘法（按符号加减） |
| 5 | 循环累乘算层数溢出 | **程序跑 10 分钟没结果**（死循环） | 按位宽直接算层数 |
| 6 | PowerShell 5.1 按 GBK 读 UTF-8 | `.env` 键值被中文注释吞掉；`.ps1` 解析错 | `.ps1` 只用 ASCII；`.env` 显式指定 UTF-8 |
| 7 | `BigInteger.longValue()` 有符号截断 | 15 素数时外部乘积全错（低字为负 → 系数变 p−4） | 超 64 位的量一律用大整数取模 |
| 8 | 素数生成重复 | CRT 逆元不存在 | 从上一个素数之后继续找 + 显式查重 |
| 9 | 素数候选向下对齐 | 又搜回上一个素数 | 候选必须**向上**对齐到 ≡1 (mod 2N) |
| 10 | LWE 用 double 做模数切换 | a[i] ~ 2^32 时超过 double 尾数，舍入错 | 改用大整数精确舍入 |

> 第 7 条的排查只花了很短时间，**因为测试用例把范围夹死了**：μ=0 过、μ=X^k 过、只有 μ=常数 失败
> → 直接指向"只有 `constant()` 会碰 q"这个事实。**保持用例覆盖不同代码路径，比优化速度更重要。**

## 九、一句话总结

- **LWE** 提供盲旋转的输入（加密索引），模数必须是 **2N**；
- **RLWE** 承载数据与累加器，模数是**多素数大模数**（论文 438 位，我们到 451 位）；
- **RGSW** 是评估材料，与 RLWE 同模数，负责"保密的选择"；
- 三层的**自检全绿**，**两个模数不同是设计而非 bug**，连接点是**模数切换**；
- 下一步只剩**把 CMUX 按位串成循环**（盲旋转本体）。
