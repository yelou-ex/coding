## 二、为什么这不是"小瑕疵"

### 2.1 LWE 的安全性**完全来自噪声**

`β = ⟨a,s⟩ + r` 这种无噪声版本：

- 给定 `(a, β)`，`⟨a,s⟩` 可以用**高斯消元直接解出 `s`** → **零安全**
- 论文对 `r_a` 的隐私保证（服务器不知道查哪一行）在这种版本下**完全不成立**：服务器能恢复 `s`

**所以那个"跑通"演示的是一个能跑、但没有任何隐私的版本。**

### 2.2 加噪声不是"打折扣"，而是**直接崩**

实测（`NoiseImpact`，N=2048、d=32、50 组/档）：

| 噪声 σ | 命中率 | 取错的行偏移 |
|---|---|---|
| **0** | **50/50 = 100%** | — ← 端到端演示的前提 |
| 1 | 23/50 = 46% | 1.2 格 |
| 2 | 6/50 = 12% | 2.0 格 |
| 4 | 4/50 = 8% | 3.6 格 |
| 8 | 2/50 = 4% | 6.9 格 |
| 16 | 0/50 = 0% | 8.8 格 |

**论文参数 σ² = 3.192（σ ≈ 1.79）→ 落在 12%~46% 之间，即大部分查询会取错行。**

**错的形态是"整行偏移"，不是"数值噪声"** —— README §3.4 的原话：
`e=+1 → p[r+1]`、`e=-1 → p[r-1]`。

## 三、根因（README §3.4 已记录）

```java
for (i) { cur = cmux(bk[i], cur, multiplyPowerOfX(cur, a[i])); }
return multiplyPowerOfX(cur, -b);      // ← 相位直接当指数，没有取整/吸收噪声的环节
```

**没有任何一步把"带噪声的相位"变成"精确的旋转指数"。**

### 3.1 一个我这次才想清的数学事实

**噪声一旦进了指数，就再也消不掉了：**

相位 `= ⟨a,s⟩ + r + e` ⟹ 累加器 `= X^{−(⟨a,s⟩+r+e)} = X^{−r}·X^{−e}`

`X^{−e}` 是**非整数次幂** —— 相当于把多项式系数平移非整数格。
**"末尾对相位取整"是无效的**，因为噪声已经在前面每一轮 CMUX 里体现过了。

**所以消噪必须在"噪声还没进指数之前"完成。**

## 八、★ 根因找到了（2026-10-16）：论文的 LWE 定义里有缩放因子 Δ

### 8.1 论文原文（§2.3，L363）

```
b = ⟨a, s⟩ + Δ·m + e   (mod q)
```
> *"Δ is a scaling factor determined by the plaintext encoding."*
> *"Correct decryption recovers m as long as the accumulated error remains
>  below the decoding bound."*

### 8.2 而我们的实现用的是 Δ = 1

```java
BlindRotateOps.lweEncryptIndex:   beta = floorMod(sum + r, qL)   // ← 没有 Δ
```

**噪声容限不是固定值，而是 `Δ/2`：**

| Δ | 噪声容限 `Δ/2` | 论文参数 σ ≈ 1.79 下（需 `Δ/2 > 3σ ≈ 5.4`） |
|---|---|---|
| **1**（我们用的） | **0.5** | ❌ 远不够 → `e=±1` 就取错行 |
| 16 | 8 | ✅ 够 |
| 64 | 32 | ✅ 宽裕 |
| 256 | 128 | ✅ 极宽裕 |

**⇒ "索引噪声零容忍"的本质是「我们把 Δ 取成了 1」。**
论文参数下只要 **Δ ≥ 11** 就能 100% 取对行。

### 8.3 与 README §3.4 三个候选的关系

| README 候选 | 正确对应 |
|---|---|
| (a) 载荷布局留间隙 | 扩大**载荷**的容差（另一条路） |
| **(b) 索引密文噪声被压到 ≈0** | ← **不是"压噪声"，而是"加大 Δ"**。噪声没变小，是**信号被放大**，相对容限 `Δ/2` 变宽 |
| (c) BlindRotate 内部还有一步 | `BitDecomp` 的舍入测试多项式 |

**候选 (b) 的正确形式就是论文的 `Δ·m`** —— 纯参数修正，**不改算法结构**。

### 8.4 正确的实现式

```
编码：β = ⟨a,s⟩ + Δ·r + e
还原：cur ← mulX(cur, − Δ·round(β / Δ))      ← 舍入到最近的 Δ 倍数
约束：Δ·R ≤ q_L / 2                            （索引本身不能越界）
```

**状态**：`CapeLweScaling.java` 里我按这个式子试了，但 Δ≥16 时结果全 0
—— **还原式的实现没调对**（`X^{−Δ·r̂}` 与 CMUX 累积的 `⟨a,s⟩` 量级没对齐）。
**但依据已明确，属于实现细节，不再是"不知道怎么做"。**
