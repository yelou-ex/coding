## 一、⚠️ 差异 1：指纹是 48 bit，不是 40 bit；且不是一个字段

### 原始说明
```
Payload_i = [fp, m_{K_i}, v_1, b_{v_1}[0], …]
             ↑B_0  ↑B_1   ↑B_2
```
暗示 `fp` 占**一个**字段 `B_0`，40 bit。

### 代码实际
```java
// PayloadFingerprint.limbs
return new int[]{u16(digest,0), u16(digest,2), u16(digest,4)};   // 3 个 16-bit limb
```
```java
// PayloadBlockProvider.fill
if (index < 3) output[local] = fingerprint[index];               // 下标 0,1,2
```

| 项 | 值 |
|---|---|
| 指纹位数 | **48 bit**（3 × 16） |
| 占用字段 | **3 个**：下标 `0`、`1`、`2` |
| 为什么这样 | payload 的每个字段必须落在 `Z_t` 的 fast plain lift 窗口（±t/2，t=65537）内 —— **16-bit limb 天然安全**，而一个 40/48-bit 的大数直接放会超窗 |

**注意**：论文参数里 `fingerprintBits = 40`（`CapeParameters.paperAligned()`），但代码实现是**取 3 个 16-bit limb = 48 bit**。这是实现层面的取法差异，不是错误，但**文档与代码必须统一口径**，否则计算 `B_pay` 会差一个字段。

### 写代码时按这个来
```
指纹 = 3 个字段（下标 0,1,2），每个 16 bit
B_pay = 3(指纹) + 2(值个数) + m·(2 + ℓ_BF)
```

## 二、⚠️ 差异 2：`u ↔ (r,c)` 的映射方向

### 原始说明
```
BFF 位置 u = r·C + c   →  矩阵条目 (r, c)
```
（`r` 是行、`c` 是列，行优先）

### 代码实际
```java
// BffMatrixLayout.coefficient
int slot = row + column * rows;      // ← 列优先
```
```java
// DiskBffEncoder：落盘顺序
"blockFormat": "big-endian signed int32 [column][payloadBlock][row]"
```

| 项 | 原始说明 | 代码 |
|---|---|---|
| 位置公式 | `u = r·C + c`（行优先） | `slot = row + column·rows`（**列优先**） |
| 等价写法 | — | `u = c·R + r` |
| 正逆变换 | — | `row = slot % rows`，`column = slot / rows` |

**两者都可行**，只是行列编排不同。关键是**编码端与检索端必须用同一个**。
代码统一用列优先，且这个顺序被写进 `bff-manifest.json` 的 `blockFormat` 字段，
**跨语言实现必须严格复现**。

### 写代码时按这个来
```
slot → (row, column):   row = slot % rows,  column = slot / rows
(column, row) → slot:   slot = row + column * rows
```

## 三、⚠️ 差异 3（最关键）：Pack 后字段落在**槽位**，不是**系数**

### 原始说明
> ### 3.1 Pack 后的 RLWE 多项式结构
> | **系数**索引 | 存储内容 |
> |---|---|
> | 0 | 指纹 |
> | 1 | 数量 m_K |
> | 2 | 值 v_1 |
> | 3 | b_{v_1}[0] |
> …
>
> **Bloom 过滤器被切成单个位，每位占一个系数（或槽位）。**

### 代码实际 —— 这个"（或槽位）"的含糊正是必须澄清的点

lou 在 `4448d39` 里专门做了裁决实验（`BloomInnerProductProbe`），结论是：

> **二进制同态内积只有【槽位域】才对。**
> 在【系数域】下 `CtCtMul` 是**卷积**，不是逐位相乘 —— 四组实验全错。

实测数据（`BloomInnerProductProbe`，本机复现 @ **N=8192**）：

```
[truth] ⟨a,b⟩ = 547 ;  |a| = 2731 ;  |b| = 1639 ;  |a|·|b| = 4476109

槽位域：
  [PASS] A1 CtCtMul 得到逐槽【乘积】= 逐槽 AND     槽位错 0/8192
  [PASS] A2 槽位内折叠（CtRotate(·,2^r)）得到内积
         槽 0 全折叠 = 274（期望 274）；槽 1 全折叠 = 273（期望 273）
         两者相加 = 547  vs  ⟨a,b⟩ = 547          ✅

系数域：
  [PASS] B0 语义确认：Plaintext(long[]) 是【系数】语义（不是槽位）
  [PASS] B1 负对照成立：全系数之和 = |a|·|b|，与 ⟨a,b⟩ 无关

       向量      ⟨a,b⟩ mod t   |a|·|b| mod t   全系数 mod t
       3|5       547          19593           1639
       7|11      107          20414            959
       2|3      1366          44886           4096
       9|4       228          30692           1138
```

**为什么系数域必错**：
```
Σ_k (a ⊛ b)_k = (Σ_i a_i)·(Σ_j b_j) = |a|·|b|
```
折叠把所有系数加起来，得到的是**两个汉明重量之积**，与查询内容完全无关。

> 上表里 `|a|·|b| mod t` 与"全系数 mod t"的关系是
> `全系数 = floor(|a|·|b| / t)`（因为 `|a|·|b|` 高达 4.48e6，而 `t = 65537`，
> 所以全系数其实跨了 68 个 t 周期）。**无论哪种读法都与 ⟨a,b⟩ 无关**，
> 这正是"系数域算不出内积"的量化证据。

**额外结论**：`Plaintext(long[])` 是**系数语义**。要让值落在槽位上，必须走 `BatchEncoder`。
这条对写 Pack 很关键 —— 不是"用哪个构造函数"的问题，是**语义**问题。

**为什么**：
```
槽位域：CtCtMul = 逐槽位相乘 → 配合 CtRotate/CtCtAdd 折叠 = 内积   ✅
系数域：CtCtMul = 多项式卷积 → 会跨系数串扰，不是内积              ❌
```

所以 **Pack 必须把每个字段放进一个槽位，而不是系数**。
正是为此 lou 写了 `RingPack.java`（把 `packFromSample` 换成真正的 Ring Packing）：

```
SwK[j][k] = RLWE( B^k · s_j )      把 LWE 私钥系数当常数加密
sum       = Σ_j Σ_k d_{j,k}·SwK[j][k]   → 消息 = ⟨a,s⟩（纯常数）
sum      -= b                       → 消息 = b − ⟨a,s⟩ = m
selected  = sum ⊗ E_i               → 只落槽位 slots[i]
packed    = Σ_i selected            → 多条 LWE → 一个 RLWE
```

**"纯常数"是关键**：相位是常数，乘槽位选择子 `E_i` 才不会把别的槽的值带进来。

### 写代码时按这个来
| 环节 | 域 |
|---|---|
| BFF 编码、`P_{c,b}(X)` 构造 | 系数域（`Σ_r D[r,c,b]·X^r`） |
| 列选择 / 盲旋转 / SampleExtract_0 | 系数域 ↔ 由 `BlindRotate` 内部处理 |
| **Pack 的输出** | **槽位域**（每字段一个槽位） |
| **Bloom 打分** | **槽位域**（`BloomScoring`） |

## 四、补充：一处表述不精确

原始说明写：
```
L_BFF = R × C
```
代码实际是 **`R × C ≥ L_BFF`**（多余槽位补 0）：

```java
int rows    = Math.min(N, Math.max(1, (int) Math.ceil(Math.sqrt(tableLength))));
int columns = (int) Math.ceil((double) tableLength / rows);
// 于是 rows*columns >= tableLength
```
`BffMatrixLayout.coefficient` 里对越界槽位返回 0：
```java
return slot < bff.tableLength() ? bff.coefficientAt(slot, payloadBlock) : 0;
```

## 六、一句话总结（给写代码的人）

> **框架照原说明做**：Bloom 每位一个字段、一个多项式、一个系数。
> **但三处必须按代码**：指纹是 **3 个 16-bit 字段**（不是 1 个 40-bit）；
> 位置映射用 **`slot = row + column·rows`**（列优先）；
> **Pack 的输出进槽位而不是系数**，否则 `CtCtMul` 会变成卷积，内积算错。
