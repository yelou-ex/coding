# CAPE 复现：保真度与偏离说明

> **这份文档回答一个问题**：我们复现的这套东西，**哪些是论文的 CAPE，哪些是我们的实现选择，
> 哪些论文主张因此不能引用**。
>
> **写于**：2026-10-14。**依据**：本轮所有实测（全部可复跑，命令见各节）+
> 论文原文（`coding/pdf-extract/out_cape.txt`）+ ChalametPIR 原文。
>
> **一句话**：**CAPE 的机制在演示尺度上跑通了（有可跑断言），但协议形态还没对上论文。**
> 因此**不能声称"实现了论文的 CAPE"**，也**不能引用论文的几项安全主张** —— 逐条列在 §三。

## 一、先说结论：能声称什么 / 不能声称什么

### ✅ 可以声称

| # | 声明 | 依据 |
|---|---|---|
| 1 | **CAPE 的核心机制已实现并逐条验证**：加密 Bloom 打分、每候选密文分数、`Dec(ct_score) = τ` 判定、指纹 ⊥ | `selftestCape` **9 PASS / 0 FAIL**；`CapeDefaultPathTest` / `CapeAlgorithm2Diag` 全绿 |

| 3 | **判定承重**：破坏 `ct_score`（置零 / 翻一位）⇒ 一条都不接受 | 负对照 N1 / N1b，**在过线后的字节上**做的 |
| 4 | **候选值不再由服务器告知**：客户端从 `ct_v`（`ctPay`）自己解出 `V_{K₁}` | §四 ①；`V_K1=[5706,93,185]` 客户端解出 |
| 5 | **BFF 参数化与 ChalametPIR 逐条对上**，且 `L_BFF ≤ ⌈1.125n⌉` 成立 | `CapeBffParamDiag`；报告 `P1-4-*` |
| 6 | **`d` 的语义已钉死并记录代价** | 报告 `P1-3-*` |

### ❌ 不能声称（每一条都有实测依据）

| # | 不能声称 | 为什么 |
|---|---|---|
| 1 | **"实现了论文的 CAPE"** | §三 的 7 条偏离里有 4 条是**协议级**的 |

## 三、协议层：7 条偏离（这是"不算完整 CAPE"的全部原因）

> 记号：**根因组** = 由同一个架构决定引起的。

### A. `q^col` 是明文列号（论文 QUERY 5 + 附录 D.2）

* **论文**：`q^col_a = RLWE.Enc_{s_R}(e)` —— 选择子是密文；
  附录 D.2 依赖 *"a column selector is indistinguishable by RLWE IND-CPA security"*。
* **我们**：`colIdx` 是**明文入参**，one-hot 选择子由服务端自造。
* **后果**：**D.2 的混合论证不成立。**
* **状态**：试过（P1-1），卡在 native `multiply_plain` 崩溃；代码已回滚，有交接文档。

### B. `Pack` 没做（论文 ANSWER 13）　【根因组】

* **论文**：`resp ← Pack({ct_{pay,b}})` —— 把一行的 `B_pay` 条样本打包成**一条**密文。
* **我们**：直接发每候选一条分数密文。

### C. 候选 Bloom 密文不是"检索出来的那条"（D2，论文 ANSWER 4 的 `ct_{B^F_j}`）　【根因组】

* **论文**：`ct_{B^F_j}` 是**从 `resp_anc` 里取出**的密文。
* **我们**：服务端把解出来的位**重新加密**。
* **真障碍**：`SampleExtract` 输出在 `q_R` 上，喂 `RingPack` 要缩放到 `Z_t`，
  而该缩放引入 ≈√N 的舍入噪声（实测 |残差| 最大 ≈30，是 Bloom 位值 1 的十几~几十倍）。

### D. `q^row` 无噪声（D1）**且 `s_L` 被绑在 `s_R` 上**　【根因组】

* **论文**：SETUP 3 是 `generate HE keys sk = (s_L, s_R)` —— **两把独立密钥**；
  §2.5 的 `LWE.Enc` 是 `b = ⟨a,s⟩ + Δ·m + e`。
* **我们**：`b = ⟨a,s⟩ + r_a`（`Δ=1, e=0`），且 **`s_L` 必须逐位等于 `s_R`**。
* **为什么必须相等**（实算，`selftestCape` 的 P1-3 段）：
  ```
  净旋转 = Σ a_i·(s_R,i − s_L,i) − r_a
  要它 ≡ −r_a，必须 Σ a_i·(s_R,i − s_L,i) ≡ 0 对**所有** a 成立
  ⟺ s_R == s_L 逐位
  ```
  实测：差 **1 位** ⇒ 行号偏 **5767**。
* **后果**：**不能引用论文的 `(s_L,s_R)` 独立性论证**；`d=16` 也不是论文的 LWE 安全参数。

### E. 单 JVM、密钥未隔离

同一个 JVM 既持 `sk` 又跑查询 ⇒ **"服务器无法解密"这句话没法验证**。
（响应数据流是真的过线 —— 字节往返已实测 —— 但密钥持有者仍是同一个。）

### F. BFF 位置函数 `h_i` 没实现

* **论文**（ChalametPIR Alg.1 L8-10）：`h_i(K) = (N/s)(h''(K)−1) + h'(K‖i)`，
  一个关键词有 **k 个位置、分布在 k 个连续段**。
* **我们**：一个关键词**只有 1 个位置**（一个 cell），k 条路取该 cell 内连续 k 行；
  段内偏移用**线性探测**。
* **另**：我们的 `s = cellsPerCol = 5`（论文闭式给 64）；`L_BFF` 是**网格几何的副产品**，
  不是按 n 算的设计参数。详见 `P1-4-*` 报告的 F1–F4。

### G. 参数口径差（论文允许自选，但必须记录）

| 项 | 论文 | 我们 |
|---|---|---|
| `N` | 16384 | **8192** |
| `d` | 512 | **16** |
| `ε_BF` | 2⁻²⁰ | **2⁻⁶** |
| `ℓ_BF` | `ℓ(n,ε_BF)`，未给值 | **18** |
| `B_pay` | `2+m`（m ≤ 2¹¹） | **59** |
| `sk` | `(s_L, s_R)` 两把 | **`s_L == s_R`** |
| `t` | 一把、一个 | **两条信道两个 `t`**（native 2³² / 打分 65537） |
| `R` | SETUP 只给约束，**未给值** | **16** |

## 四、⭐ 三条缺口是同一个根因（本文最重要的结论）

原先 B（Pack）、C（D2）、D（`s_L` 独立性）在清单里是**三条独立的**。
查过 `rgsw-lab/LWE_RLWE打包_RingPack_调研.md` §障碍 1 之后，**它们是同一个东西的三个面**：

```
论文 SETUP 3:  sk = (s_L, s_R)    —— 两把**独立**密钥，且 LWE 维数 d ≪ N
我们的实现  :  s_L 必须逐位等于 s_R（"LWE-in-RLWE"，维数 = N）
```

| 缺口 | 为什么被同一个根因卡住 |
|---|---|
| **Pack** | ring packing 的交换密钥要 `n·⌈log_B q⌉` 条密文。我们 `n = N`：`N=8192` 时 **SwK ≈ 12 GB**，`N=16384` 时 **~16 GB** ⇒ **不做独立密钥，Pack 装不下** |
| **D2 候选密文来源** | 论文的 `ct_{B^F_j}` 是**服务端从检索结果 Pack 出来的**；没有 Pack 只能"解出来再重新加密" |
| **`q^row` 加噪声** | `s_L == s_R` 时服务器自己就能算 `⟨a,s_L⟩`，`β` 掩不住任何东西 |

**两条独立推导得到同一结论**：`RingPack` 调研文档自己写着 ——
*"要上 ring packing，可能必须放弃『维数 = N』，改成真正的 `sk = (s_L, s_R)` 两把独立密钥……
**这反过来证明：论文里 `s_L` 与 `s_R` 很可能确实是两把独立密钥，LWE-in-RLWE 是我们的简化。**"*

**⇒ 所以这不是"三个待办"，是"一个架构决定"的三个后果。**
**代价**：改独立密钥**必然连带重做盲旋转的相位口径**（因为 `s_L==s_R` 正是它现在能跑通的原因），
而且 `d` 要从 16 提到论文量级才够掩蔽噪声。

## 五、我们**主动选择**的实现决定（不是遗漏，是权衡）

| # | 决定 | 代价 | 替代方案 |
|---|---|---|---|
| 1 | **LWE-in-RLWE**（`s_L == s_R`、维数 = N） | 见 §四：Pack / D2 / 噪声三处被卡 | 改 `sk=(s_L,s_R)`，但那要重做盲旋转相位口径 |
| 2 | **没实现 `h_i`，用线性探测** | 不是 ChalametPIR 那套 BFF；`L_BFF` 来历不同 | 实现 `h_i` + k 个位置（要动表构造与三路 share 语义） |
| 3 | **两条 SEAL 信道两个 `t`** | 论文只有一把 `sk`、一个 `t` | `BatchEncoder` 要求 `t≡1 (mod 2N)`，`t=2³²` 下**根本构造不出来**（实测） |
| 4 | **演示尺度参数** | 见 §三 G | 上论文参数要连着解 §四 |
| 5 | **索引 `u` 用"哈希 + 线性探测"而非论文 `h_a`** | 位置分布不同 | 属 F 那一组 |
| 6 | **P1-2 用块布局（载荷复制）而非改盲旋转** | 偏离论文 SETUP 14（一行一个系数） | 改盲旋转内部做舍入/比特提取 |

> **第 1 条是根**，其余五条要么是它的后果、要么是独立的小口子。

```
① valueId → ct_v（服务器不再告知候选值身份）   ✅ 已完成
② Pack                                        ⛔ 卡在 §四 的根因上（SwK ≈ 12 GB）
```

**⇒ ② 与 ④ 不该再单独试** —— 它们要的不是实现，是 §四 那个决定。
