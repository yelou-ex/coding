## 一、论文说的是什么

```
A1 SETUP  3: Select public parameters (N,d,t,q), and generate HE keys sk = (s_L, s_R).
A1 QUERY  5: q_a = ( q^col_a, q^row_a ) = ( RLWE.Enc_{s_R}(e), LWE.Enc_{s_L}(r_a) )
A2 DECODE 8: s_j <- Dec_{s_R}(ct_score,j)
```

⇒ **`d` 是 `LWE.Enc_{s_L}` 里 `a ∈ Z_q^d` 的维数**，而 **`s_L` 与 `s_R` 是 SETUP 里
一起生成的两把独立密钥**。这一点是本项的关键，下面 §三 会用到。

## 二、实测事实（全部可复跑）

### 2.1 秘密的真实三值分布

新加了诊断入口 `nativeSecretHistogram`（**为什么必须新开一个入口见 §2.2**），
对全部 8192 个系数统计：

| 系数值 | 个数 | 密度 |
|---|---|---|
| `−1` | 2725 | 0.3326 |
| `0` | 2798 | **0.3416** |
| `+1` | 2669 | 0.3258 |
| 非三值 | **0** | —— |

⇒ 秘密确实是**三值且均匀**的，与 SEAL 4.0.0 源码一致：

```cpp
// native/src/seal/util/rlwe.cpp : sample_poly_ternary
uniform_int_distribution<uint64_t> dist(0, 2);      // rand ∈ {0,1,2} 均匀
uint64_t flag = -static_cast<uint64_t>(rand == 0);
*get<0>(J) = rand + (flag & get<1>(J).value()) - 1; // rand=0 -> -1, 1 -> 0, 2 -> +1
```

而 `KeyGenerator::generate_sk` **只**调用 `sample_poly_ternary`（全库搜过，没有第二个来源）。

### 2.2 ⚠️ 观察工具本身抹平了语义

`secret_bits` 的映射是：

```cpp
bits[i] = (v == 1 || v == 0) ? v : 0;      // −1 与真 0 都被记成 0
```

**它分不清 −1 和真 0。** 而 `nativeSecretBits` 就是它的包装 ——
也就是说**项目里一直用来"看秘密"的那个入口，恰恰看不到本项要问的东西**。
这解释了为什么 `d` 的语义能一路走到今天：**唯一的观察窗口是有损的**。

> 这条本身值得单独记：**当一个结论所依赖的观测通道有损时，绿灯说明不了任何事。**

### 2.3 恒等轮的真实比例：**≈1/3，不是 2/3**

恒等轮来自 `s_i == 0`（`CMUX` 不动 —— 见 `blind_rotate` 里的
`if (a[i] % two_n == 0) continue;` 是**另一条**来源，与三值无关）。
所以：

> **恒等轮比例 = 零的密度 = 0.3416 ≈ 1/3**

**⇒ 规划书 §1.3 与 §三 P1-3 两处写的"约 2/3 的轮是恒等"<u>方向写反了</u>。**
正确的说法是 **"约 2/3 的轮在做真的 CMUX"** —— 旋转机构被压得比原先记载的**更满**，
这是**好消息**。

**顺带一条方法论教训**：`d = 16` 时该比例的标准差是
`sqrt((1/3)(2/3)/16) ≈ 0.118`，**1/3 与 2/3 都常落在 ±3σ 内** ——
小样本根本判不出这两个数。我第一次读的时候就是拿 `d=16` 的观察值当结论、
自己把方向搞反了一次。**必须用全量直方图，不能用投影 + 小样本。**

### 2.4 另一条恒等轮来源（可忽略，但要归对因）

`blind_rotate` 里 `a[i] ≡ 0 (mod 2N)` 时那一轮也是恒等（因为 CMUX 两支相同、
SEAL 会判 transparent）。客户端均匀采样 `a[i] ∈ [0, 2N)`，所以概率是

```
d / (2N) = 16 / 16384 ≈ 0.00098        (d=16, N=8192)
```

**可忽略，但它与三值秘密无关** —— 归因时不要混为一谈。

## 三、真正的问题不是恒等轮，而是 `s_L` 被绑在 `s_R` 上

这是实测中最硬的一条。盲旋转**实际**做的是：

```
X^{ Σ a_i·s_i(bsk) − beta }          而 beta = ⟨a, s_L⟩ + r_a
⇒ 净旋转 = Σ a_i·( s_R,i − s_L,i ) − r_a
⇒ 要它 ≡ −r_a，必须 **Σ a_i·(s_R,i − s_L,i) ≡ 0 (mod 2N)**
```

而这个式子**对所有 `a` 都成立 ⟺ `s_R == s_L` 逐位相等**。实算（差异放在下标 0，
其 `a[0] = 1234567 ≠ 0`）：

| 情形 | 净旋转量 | 结果 |
|---|---|---|
| `s_L == s_R` | 16377 | ≡ `−r_a` = 16377 ✅ |
| `s_L` 与 `s_R` 差 **1 位** | 5760 | 行号**偏 5767** ❌ |

⇒ **论文的 `sk = (s_L, s_R)` 两把独立密钥，在当前实现里被强制成同一把。**
这不是"参数没调好"，是**结构与当前盲旋转口径冲突**——
而且它**和 P1-2（索引噪声）卡在同一个结构点上**
（两者都是"`beta` 里的东西必须与 `bsk` 完全对齐"的直接后果）。

## 四、为什么选 (b) 而不是 (a)

规划书给的两条路：

| 路 | 内容 | 本轮裁决 |
|---|---|---|
| **(a)** | 换成 "LWE-in-RLWE"：把 `s ∈ Z_q^d` 真正作为多项式放进 RLWE 密钥 | ❌ **不选** |
| **(b)** | 保持现状，把 `d` 的语义与代价写进文档 | ✅ **选这条** |

**不选 (a) 的理由（三条，都不是"太难"）：**

1. **它与当前盲旋转口径不兼容** —— §三 已证：净旋转要等于 `−r_a`，
   必须 `s_R == s_L` 逐位。要让 `s_L` 真独立，就得**同时改 blind rotate 的相位口径
   与 `bsk` 的构造**，那正是 **P1-2** 那一块（你本轮明确要求不做）。
2. **即使做了，代价也在别处**：`RingPack` 调研已经算过 ——
   `n = N = 8192` 时交换密钥 `SwK ≈ 12 GB`，调研结论原文就是
   *"必须放弃 LWE-in-RLWE、改用论文 SETUP 写的 `sk = (s_L, s_R)` 独立密钥"*。
   也就是说 (a) 不是"把 `d` 改对"，而是**触发了另一个更大的工程缺口**。
3. **它不改变任何已经实测的结论**：`d=16` 的可跑性、`sBits` 与 `bsk` 同源的必要性、
   假阴性 = 0 —— 都不依赖"`d` 是不是论文意义上的 LWE 维数"。

**⇒ 所以本轮把 `d` 钉成如下口径（写进文档，不再含糊）：**

| 项 | 口径 |
|---|---|
| `d` 在本实现里是什么 | **RLWE 秘密 `s_R` 的系数前缀长度**，同时也是盲旋转的**轮数** |
| 它不是论文的什么 | 论文的 `d` 是 `LWE.Enc_{s_L}` 的维数，`s_L ⊥ s_R` **独立** |
| "恒等轮"的比例 | **≈1/3**（`s_i == 0`），**不是 2/3** |
| `s_L` 与 `s_R` 的关系 | **必须逐位相等**（否则净旋转偏 `Σ a_i(s_R,i − s_L,i)`） |
| 这对安全性的影响 | **不能引用论文的 `(s_L, s_R)` 独立性论证**；`d=16` 也**不是**论文的 LWE 安全参数 |

## 五、本轮**没有**做

1. **(a) 那条路**（真 LWE-in-RLWE / 独立 `s_L`）—— 与 P1-2 是同一块，见 §四。
2. `d` 的**取值探索**：现在是 `-Dcape.d`，默认 16。既然它不是论文的 LWE 维数，
   那它的取值就只是"轮数"，与安全无关 —— **但它决定了 `β` 的掩蔽强度**。
   这一层含义本节没有展开，留给需要的人。
