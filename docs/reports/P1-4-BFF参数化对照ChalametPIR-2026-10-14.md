## 一、两个出处（都是原文，不是转述）

| 出处 | 位置 | 给了什么 |
|---|---|---|
| **CAPE**（复现目标） | 附录 A · Algorithm 3 `SETUP(n,k,B,t,mu)` 第 1–7 行 | `s` 与 `L_BFF` 的闭式；并注明这两组有限尺寸取值 **"follow the parameterization of BFF used in ChalametPIR [8]"** |
| **ChalametPIR**（Celi & Davidson） | 附录 B · Algorithm 1 `setupFilter` 第 2–10 行 | **同一组公式的原始出处**；另外独有第 8–10 行的**位置函数** |

### 1.1 `s`（段大小）—— 两篇**完全一致**

```
k = 3:   s = 2^floor( log_3.33(n) + 2.25 )
k = 4:   s = 2^floor( log_2.91(n) - 0.5  )
```

两处都写成这个形状，且 **`s` 恒是 2 的幂**。CAPE 明确说它的 FusePIR 实例取 `k=3`：

> "The constructions supports `k ∈ {3,4}` locations per keyword.
>  **Our concrete FusePIR instantiation uses `k=3`**"

### 1.2 `L_BFF`（数组长度）—— 两篇**形状相同、数值不同**

**CAPE** Alg.3 第 3 / 6 行：

```
k = 3:  L_BFF = max( ceil( (0.875 + 0.25·max(1, log10(n/6)))          · n ), ceil(1.125·n) )
k = 4:  L_BFF = max( ceil( (0.77  + 0.305·max(1, log10(n/(6·10^5))))  · n ), ceil(1.075·n) )
```

**ChalametPIR** Alg.1 第 3 行（`N = c·m`）：

```
k = 3:  c = max( floor( (0.875 + 0.25·max(1, ln(10^6)/ln(m))) · m ), floor(1.125·m) )
k = 4:  c = max( floor( (0.77  + 0.305·max(1, ln(6·10^5)/ln(m))) · m ), floor(1.075·m) )
```

**两处差异，都不是笔误级别的：**

| 差异 | CAPE | ChalametPIR |
|---|---|---|
| 取整 | `ceil` | `floor` |
| 对数的那个量 | `log10(n/6)` | `ln(10^6)/ln(m)` = `6/log10(m)` |

**这两个函数不是同一个函数的换底。** 把 CAPE 的 `log10(n/6)` 展开是
`log10(n) − log10(6)`，而 Chalamet 的是 `6/log10(m)`；数值上
n=1000 时前者 2.2218、后者 2.0000，n=10⁶ 时前者 5.2218、后者 1.0000。

> **本轮不判定谁对。** 要定这件事需要看两篇 PDF 的原始排版（抽取文本里的
> 分式/上下标会串行）。**这不影响我们的结论** —— 见 `<a name="s3">`§三`</a>`。

### 1.3 位置函数 `h_i` —— **只有 ChalametPIR 有**

ChalametPIR Alg.1 第 4、8–10 行（原文）：

```
4:  Sample universal hash functions h' : {0,1}* -> [N/s] , h'' : {0,1}* -> [s]
8:  for i ∈ [k] do
9:      h_i(·) = (N/s)·( h''(·) − 1 ) + h'(· ‖ i)
10:     H[i] = h_i
```

读法：**`h''` 选段（共 `s` 段）、`h'` 选段内偏移（每段 `N/s` 个位置）**，
于是 `h_0(K), …, h_{k−1}(K)` 落在 **k 个连续段**里、各段取一个位置。
重建时把 k 个条目按分量相加 mod t 就还原载荷（`BFF.Reconstruct`）。

## 二、我们这一组参数上，论文给什么

**`n = 128`、`k = 3`**（演示库的关键词数）：

| 量 | 闭式 | 值 |
|---|---|---|
| `s` | `2^floor(log_3.33(128) + 2.25)` | **64** |
| `L_BFF`（CAPE，`ceil`） | 见 1.2 | **155**（= 1.2109·n） |
| `L_BFF`（ChalametPIR 形状） | 见 1.2 | **204**（= 1.5938·n） |
| `⌈1.125n⌉`（**渐近界本身**） | —— | **144** |

> ### ⚠️ 这里要更正规划书的一处写法
> 规划书写「论文 `≲1.125n = 144`」。**144 是渐近界 `⌈1.125·128⌉` 本身，不是论文闭式在
> n=128 上的取值** —— 论文闭式给的是 **155**（比 144 还大）。
>
> 而且 CAPE 自己的闭式**并不收敛到它声明的 1.125n**：它随 n 单调上升 ——
>
> | n | 1000 | 10000 | 100000 | 1000000 |
> |---|---|---|---|---|
> | `L_BFF/n` | 1.4310 | 1.6805 | 1.9305 | 2.1805 |
>
> 而论文正文写的是 *"For large n, the resulting array lengths **approach 1.125n**"*。
>
> **⇒ 本轮最值得记的一条结论：「照着论文的闭式抄」并不足以复现论文的量。**
> 引用 `L_BFF` 时必须说清是「渐近界」还是「有限尺寸闭式」，两者在这个 n 上差 11。

## 三、我们是什么（可跑的断言，不是散文）

`CapeBffParamDiag` 第 2、5 节把这些逐条钉死：

| 量 | 我们的做法 | 值（n=128） |
|---|---|---|
| **段大小 `s`** | **`cellsPerCol = R / maxValues`** | **5**（论文 64） |
| 列数 `C` | `⌈n / cellsPerCol⌉` | 26 |
| **`L_BFF`** | **`cellsPerCol · C`** = `5 × 26` | **130**（= 1.0156·n） |
| `dataRadius` | `(cellsPerCol−1)·maxValues + k` | 15 |

**规划书要点名的那条关系，答案是：**

```
我们 130  ≤  ⌈1.125n⌉ = 144      ✅ 界成立
我们 130  <  论文闭式 155        ✅ 比论文闭式还小
我们 130  <  Chalamet 形状 204   ✅
```

**三方比较与「用哪一家的闭式」无关** —— 我们的 130 比**两家都小**，
所以 §1.2 那条未解决的公式分歧**不影响这条结论**。

### 3.1 这条界什么时候成立（n 扫描）

我们的 `L_BFF = 5·⌈n/5⌉ < n + 5`，所以解 `n + 5 ≤ 1.125n` 得 **`n ≥ 40` 时恒成立**
（40 是**充分**条件）。暴力扫描：`n ∈ [1,400]` 里不满足的是
`[1, 2, 3, 6, 7, 8, 11, 12, 16, 21]`，**最小的可行 n 是 4**。
我们的 `n = 128` 远在其上。

> **⚠️ 但"更小"不等于"更好"。** 我们省下的余量有一部分是**靠"线性探测恰好不撞"换来的**：
> 论文的 `MappingStep` 会返回"映射失败"并换种子重来，**我们只检查"两两不同槽"**，
> 没有"分配是否可能失败"这个概念（因为每个关键词只要一个位置）。
> 已经实测的"假阴性 = 0"（`CapeTableDiag`）仍然成立，但那是**实测**，不是**构造保证**。

## 四、三处必须一起说的形态差

| # | 差在哪 | 论文 | 我们 | 后果 |
|---|---|---|---|---|
| **F1** | **`L_BFF` 的来历** | 由 `s` 与 n 的**闭式**定出 —— 是**设计参数** | `cellsPerCol·C` —— 是**网格几何的副产品** | 数值可以都落在界内，但"一个是按 n 算的、一个是刚好装下的" |
| **F2** | **"段"的用法** | 一个关键词 `→ k 个位置`，分布在 **k 个连续段**，位置由 `h_i` 定 | 一个关键词 `→ 一个 cell`；k 条路取该 cell 内**连续 k 行** | 我们满足"三路相加 = 载荷"这条**重建性质**，但 **`h_i` 那套位置函数没有实现**；段内偏移用的是**线性探测**，不是 `h'(K‖i)` |
| **F3** | **`s` 是否随 n 变** | **随 n 变**（`s(128)=64`、`s(100000)=2048`） | **恒为 5**（由 `R/maxValues` 定，与 n 无关；n 只影响列数 C） | 我们的"分段粒度"是部署参数，不是按数据规模选的 |
| **F4** | 段内位置的**取值数** | 一个段里有 `s = 64` 个位置 | 一个 cell 只有 `maxValues = 3` 行 | **量级差 21 倍** |

**F1–F4 都不影响已经实测的结论**（几何、三路重建、假阴性 = 0），
但它们是「**我们不是在跑 ChalametPIR 那套 BFF**」的证据 —— 引用时不能省。
