## 二、lou 的新提交做了什么

他做的正是我上轮指出**唯一还缺的那块**（README 整改项 A4：「`CtCtMul` + `Σ CtRotate` 打分循环没写」）——
而且比"把循环写出来"更深入：他发现**前提就错了**。

### 核心洞见（很关键，值得记住）

> **`packFromSample` 不是论文的 Pack。**
>
> - `packFromSample` 只是 **SampleExtract 的逆**（单样本 ↔ 单系数），产出落在**系数域**；
> - 而**二进制同态内积只有槽位域才对** —— 在系数域下 `CtCtMul` 是**卷积**，不是逐位相乘；
> - 所以 `PackGoalCheck` 的四条子目标全是未达成 —— **那四条测的不是论文的 Pack**。

修正做法（`RingPack.java`）：

```
SwK[j][k] = RLWE( B^k · s_j mod t )      把 LWE 私钥系数当常数加密
sum       = Σ_j Σ_k d_{j,k} · SwK[j][k]   消息 = ⟨a,s⟩（纯常数）
sum      -= b                             用「常数明文 × RLWE(1)」实现
sum       = −sum                          消息 = b − ⟨a,s⟩ = m（纯常数）
selected  = sum ⊗ E_i                      只落在槽 slots[i]
packed    = Σ_i selected                   ← 多条 LWE → 一个 RLWE
```

**「纯常数」是关键**：相位是常数，乘槽位选择子 `E_i` 才不会把别处（其他槽）的值带进来。

### BloomScoring 5/5 —— 这就是 A4 缺的那一环

```
[PASS] C1 行和候选都含 → b_qry 全部位对应，s = τ
[PASS] C2 候选 = b_qry 子集 → s = τ
[PASS] C3 漏 1 位 → s = τ−1，应不命中
[PASS] C4 漏 5 位 → s = τ−5，应不命中
[PASS] C5 空候选 → s = 0
=== Bloom 槽位打分全部通过（CtCtMul + 折叠 = 二进制同态内积）===
```

判据设计得很好：**不只是"命中时等于 τ"，还验了"漏 k 位就恰好少 k"** —— 这排除了"分数碰巧对"。

### RingPack 6/6（N=8192）

```
[PASS] P1 16 条 LWE 比特 → 一个 RLWE 密文；槽位错 0，未写入槽非零 0
[PASS] P2 打包产物【直接】喂 BloomScoring → 槽位域二进制同态内积正确   ← A4 的判据
[PASS] P3 负对照：查询平移一格，得分跟着变（排除常数巧合）
[PASS] P4 LWE 维数 n = 8 / 32 / 128 / 512 全部正确
       n=8 → 24 条密钥 / 488 ms ；n=512 → 1536 条密钥 / 24092 ms
[PASS] P5a 缩放后的 LWE 经同态路径精确搬运 → 0 误差
[PASS] P5b 缩放噪声随 n 只按 √n 增长：n=8192 最大偏差 66 vs 半窗 32768（496 倍余量）
```

**P5b 的余量很关键**：`n = N = 8192` 时噪声只有半窗的 1/496，说明**缩放不是瓶颈**。

### ⚠️ 一个遗留问题：`BloomInnerProductProbe` 在默认参数下崩溃

```
Exception in thread "main" java.lang.IllegalArgumentException:
  keyswitching is not supported by the context
  at KeyGenerator.createRelinKeys(KeyGenerator.java:387)
  at com.fusepir.rgsw.BloomInnerProductProbe.main(BloomInnerProductProbe.java:64)
[params] N=2048, 素数=1(54 bit) 工作层=1(54 bit)
```

**原因**：它默认 `N=2048`，而 N=2048 下**只有 1 个工作素数**，重线性化需要密钥切换 —— 单素数上下文不支持。

**这个坑 lou 自己已经知道并在提交里写了**：

> `Mpc4jRgsw`：新增 `relinKeys()`（`CtCtMul` 必需；**N=2048 只有 1 个工作素数会抛 keyswitching is not supported by the context**）

只是**他没把这个旧测试的默认 N 一起改**。属小疏漏，不影响主线（它的结论已被 `BloomScoring` 独立验证）。

**修法**：把 `BloomInnerProductProbe` 的默认 N 从 2048 改成 8192（或 4096，参考 `RingPack` 的取值）。

## 四、关键参数边界（lou 实测 + 我复现）

| 项 | 结论 |
|---|---|
| **N = 4096** | 打包（P1）过，但**打分侧崩** —— 多一次 `CtCtMul` + 重线性化 + 折叠，噪声爆掉 |
| **N = 8192** | **起步可用**（4 个工作素数 / 174 bit） |
| `t = 65537` | 给缩放留的空间绰绰有余（余量 496 倍） |
| 重线性化 | 需要 **≥ 2 个工作素数**（BFV 保留最后一个作 `q_last`） |

> ⚠️ 注意：这与我之前定的 **`testMinimal()` 用 N=4096** 不冲突 ——
> 那是**明文侧**（BFF/Bloom 编码）的最小参数；而 RingPack + 打分是**密文侧**，
> 需要 N=8192。两者用途不同，别混用。
