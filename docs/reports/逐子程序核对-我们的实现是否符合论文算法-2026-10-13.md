## 论文原文（坐标还原，已校对）

### Algorithm 1 FusePIR（p.8）

```
SETUP(1^λ, DB = {K_i → V_{K_i} = {v_{i,1},...,v_{i,m_i}}}_{i=1}^n)
1: (D, H, fp) ← BFF.Setup(n, 3)
2: L_BFF ← |D|,  m ← max_{i∈[n]} |V_{K_i}|
3: Select public parameters (N, d, t, q), and generate HE keys sk = (s_L, s_R)
4: Select R, C such that RC ≥ L_BFF, R ≤ N
5: for i = 1 to n do
6:   Pad V_{K_i} to m values and set y_{K_i} ← fp(K_i) ‖ m_i ‖ v_{i,1} ‖ … ‖ v_{i,m} ∈ Z_t^{B_pay}
7: end for
8: (D, H) ← BFF.Encode(D, H, {(K_i, y_{K_i})}_{i=1}^n)
9: for u = L_BFF to RC − 1 do
10:  D[u] ← 0 ∈ Z_t^{B_pay}
11: end for
12: for c = 0 to C−1 do
13:   for b = 1 to B_pay do
14:     P_{c,b}(X) ← Σ_{r=0}^{R−1} D[r + cR][b] · X^r
15:   end for
16: end for
17: pp ← (H, fp, R, C, N, d, t, q)
18: st_S ← ({P_{c,b}}_{c,b}, pp)
19: return (pp, st_S, sk)

QUERY(pp, sk, K)
1: q ← []
2: for a = 0 to 2 do
3:   u_a ← h_a(K),  r_a ← u_a mod R,  c_a ← ⌊u_a/R⌋
4:   e ← (0,...,0, 1, 0,...,0) ∈ {0,1}^C, with the 1 at index c_a
5:   q_a = (q^col_a, q^row_a) = (RLWE.Enc_{s_R}(e), LWE.Enc_{s_L}(r_a))
6: end for
7: q := (q_0, q_1, q_2), st_C ← K
8: return (q, st_C)

ANSWER(st_S, q)
1: Parse st_S = ({P_{c,b}}_{c,b}, pp)
2: for a = 0 to 2 do
3:   Parse (q^col_a, q^row_a) from q_a
4:   for b = 1 to B_pay do
5:     Acc_{a,b} ← Σ_{c=0}^{C−1} CtPtMul(q^col_a[c], P_{c,b}(X))
6:     Acc'_{a,b} ← BlindRotate(q^row_a, Acc_{a,b})
7:     ct_{a,b} ← SampleExtract_0(Acc'_{a,b})
8:   end for
9: end for
10: for b = 1 to B_pay do
11:   ct^pay_b ← CtCtAdd(CtCtAdd(ct_{0,b}, ct_{1,b}), ct_{2,b})
12: end for
13: resp ← Pack({ct^pay_b}_{b=1}^{B_pay})
14: return resp

DECODE(sk, st_C, resp)
1: K ← st_C
2: for each packed ciphertext ct^pay_β ∈ resp do
3:   y[β] ← Dec_{s_R}(ct^pay_β)
4: end for
5: Recover (f, m_K, v_1, ..., v_m) ← y
6: if f ≠ fp(K) then
7:   return ⊥
8: end if
9: return {v_1, ..., v_{m_K}}
```

### Algorithm 2 CAPE（p.9）

```
SETUP(1^λ, DB = {K_i → V_{K_i} = {v_{i,1},...,v_{i,m_i}}}_{i=1}^n)
1: Select public Bloom-filter parameters ℓ_BF and G = {g_1,...,g_h}
2: m ← max_{i∈[n]} |V_{K_i}|
3: for each v ∈ ∪_{i=1}^n V_{K_i} do
4:   S_v ← {K_i : v ∈ V_{K_i}}
5:   b_v ← BF.Gen(0, S_v)
6: end for
7: for i = 1 to n do
8:   V^CAPE_{K_i} ← {(v_{i,j}, b_{v_{i,j}})}_{j=1}^{m_i}
9: end for
10: DB_CAPE ← {K_i → V^CAPE_{K_i}}_{i=1}^n
11: (pp_F, st^F_S, sk) ← FusePIR.Setup(1^λ, DB_CAPE)
12: pp ← (pp_F, ℓ_BF, G, m)
13: st_S ← st^F_S
14: return (pp, st_S, sk)

QUERY(pp, sk, K = (K_1,...,K_Q))
1: (q_anc, st^C_anc) ← FusePIR.Query(pp_F, sk, K_1)
2: b_qry ← BF.Gen(0, {K_2,...,K_Q})
3: τ ← ‖b_qry‖_1
4: q_BF ← RLWE.Enc_{s_R}(b_qry)
5: q ← (q_anc, q_BF)
6: st_C ← (st^C_anc, τ)
7: return (q, st_C)

ANSWER(st_S, q)
1: Parse (q_anc, q_BF) from q
2: resp_anc ← FusePIR.Answer(st_S, q_anc)
3: Parse {(ct_{v_j}, ct_{B^F_j})}_{j=1}^m from resp_anc
4: ct_score,j ← CtCtMul(q_BF, ct_{B^F_j})
5: for r = 0 to log₂ℓ_BF − 1 do
6:   ct_score,j ← CtCtAdd(ct_score,j, CtRotate(ct_score,j, 2^r))
7: end for
8: resp ← ({ct_{v_j}, ct_score,j}_{j=1}^m)
9: return resp

DECODE(sk, st_C, resp)
1: Parse (st^C_anc, τ) from st_C, (resp_anc, {ct_score,j}_{j=1}^m) from resp
2: V_{K_1} ← FusePIR.Decode(sk, st^C_anc, resp_anc)
3: if V_{K_1} = ⊥ then return ⊥
4: end if
5: R ← ∅
6: for j = 1 to |V_{K_1}| do
7:   s_j ← Dec_{s_R}(ct_score,j)
8:   if s_j = τ then
9:     R ← R ∪ {v_j}
10:  end if
11: end for
12: return R
```

## 五条实质偏差

### ❌ D1（**安全问题**）：`b_qry` 没加密，服务器看得到明文关键词

| | 论文 | 我们 |
|---|---|---|
| A2 L992 | `q_BF ← RLWE.Enc_{s_R}(b_qry)` | `boolean[] bQry = bloomBits(others)`（**服务器进程内**）|
| A2 L985-989 | `q_anc ← FusePIR.Query(pp_F, sk, K_1)` | 客户端只发**明文关键词**；服务器 `tb.kwIndex.containsKey(k)` 自己查锚点 |

**服务器路径上出现明文关键词**：`CapeDemoService:175` 调 `bloomBits(others)`，
而 `others` 来自 HTTP body 的字符串；`bloomBits`（`CapeDemoService:272-280`）注释
自己写着 `/** BF.Gen over the non-anchor query keywords (client side). */`
—— 但它运行在**服务器进程**里。`anchorIdx`（`:169`）同样由服务器查表得到。

⇒ 论文 Appendix D.2 的混合论证（"challenge-dependent part of each FusePIR query
consists of the **encrypted** column and row selectors"）**在我们这版直接不成立**。
`qBfCt`（`CapeEndToEnd4` 里那个 `BloomScoring.encryptBloomVector`）是**独立演示**，
没接进服务链路。

> 这与 `缺陷总表.md` 的 P0-3/P0-4 是同一族，但**更严重**：P0-3 说的是"候选 Bloom 密文
> 由解密后明文重新加密"，而这里是**连查询都没加密**。

### ❌ D2（**算法核心缺失**）：`CtCtMul` + `log₂ℓ_BF` 次 `CtRotate` 的加密打分完全没实现

A2 ANSWER L878-879 是 CAPE 相对 FusePIR 的**全部增量**：

```
4: ct_score,j ← CtCtMul(q_BF, ct_{B^F_j})
5: for r = 0 to log₂ℓ_BF − 1 do
6:   ct_score,j ← CtCtAdd(ct_score,j, CtRotate(ct_score,j, 2^r))
```

我们做的是：把候选项的 Bloom 位当**明文**取回客户端，在 `CapeDemoService:221-232`
用 `boolean conj` 在**明文上**做合取判定。DECODE 侧对应 `s_j ← Dec_{s_R}(ct_score,j)`（L1077）
与 `if s_j = τ`（L1078）**都没有对应实现**。

⇒ 后果有三：
1. **安全**：候选值的成员信息明文泄露给客户端（本来只该给分数）。
2. **性能**：我们省掉了 80 次 CtCtMul（d·log₂ℓ_BF = 16×5）+ 旋转 —— 这解释了
   为什么我们的耗时口径和论文对不上，也说明**我们的 102 s 不含 CAPE 应有的这部分**。
3. **口径**：论文的 3.00 s 含这部分，我们的不含 ⇒ 拿两个数直接比是错的。

### ⚠️ D3：行选择子不是真 LWE（既有缺陷 P0-1，复核确认）

`nativeCapeAnswer`：`av[a][i]` 由 XorShift 伪随机生成，
`betav[a] = (sum + ridx[a]) mod 2N`，**没有 Δ、没有噪声项 e**。
§2.2 定义要求 `b = ⟨a,s⟩ + Δm + e (mod q)`。
⇒ 已记录在案，本次复核确认**仍是缺陷**。

### ⚠️ D4：`d` 的语义 —— 不是 LWE 维数，而是「取秘密多项式前 d 个系数当比特」

调用点 `d = 16`（`CapeDemoService:194` —— `nativeCapeAnswer(ctxHandle, d, ...)`），
而真实 `levels ∈ {6, 11}`。

`secret_bits()`（`rgsw_blindrotate.cpp:369-385`）：

```cpp
for (int i = 0; i < d; ++i) {
    std::uint64_t v = skc[i];
    bits[i] = (v == 1 || v == 0) ? (int)v : 0;   // -1 → 0
}
```

**两个实质问题：**

1. **SEAL 的 BFV 秘密是三元的 {-1,0,1}**，所以 `v == -1` 被**静默判成 0** ⇒
   等价于用指示函数 `1[s_i = 1]`，而不是 `s_i`。
2. `d = 16` 是人类选的常量，**不是**论文意义下的 LWE 维数，也不是 `levels`。
   论文 A1 L807 把 `d` 列为公开参数但**没给数值** ⇒ 无法判定对错，
   但「写死 16 而不从 `levels` 推」是**参数耦合不清**。

**是否影响正确性：不影响**（`β` 是确定性的旋转量，`|β|` 决定正确性，我们 PASS）。
**是否影响与论文的一致性：影响** —— 论文把 `d` 当 LWE 维数公开，
我们把它当"取多少位"。

### ⚠️ D5：三处「有意偏离」（功能等价，但非逐字复现）

| # | 论文 | 我们 | 位置 |
|---|---|---|---|
| D5a | A1 L817-821：把 `D[L_BFF .. RC−1]` **补零** | 先填 `1 + rand(t−1)` **随机值**，再覆写 BFF 槽 | `CapeDemoData:252-257` |
| D5b | A1 L836：`u_a ← h_a(K)`，**哈希** | `colOf[i] = i/cellsPerCol`、`rowOf[i] = (i%cellsPerCol)·maxValues` —— **哈希退化成线性下标** | `CapeDemoData:182-183` |
| D5c | A2 L1003/L1007：`b_v ← BF.Gen(0, S_v)`，`ℓ_BF = ℓ(n, ε_BF)` | 一致，但 `ε_BF = 2⁻⁶`（论文合取实验用 **2⁻²⁰**）⇒ `ℓ_BF=26`（论文量级大几个数量级） | DB meta `epsBf` |

- **D5a**：密文下不可区分、功能等价（槽被覆写），但**不是逐字复现**；随机填充让
  非 BFF 槽"满"，统计上更均匀。
- **D5b**：`h_a` 退化只影响「表看起来是否随机」，不影响正确性；
  但**它让索引与关键词身份一一对应**，配合 D1 会进一步放大可关联性。
- **D5c**：`ε_BF` 是**演示取舍**（已记录在 `Bloom适配论文与参数最小化.md`：
  提到 2⁻²⁰ 会让 `B_pay → 665 092`、单查询 324 小时）。**但它是 `B_pay` 的直接驱动量**，
  所以「我们的性能不能和论文比」有相当一部分来自这里。

## 结论

**结构上：Algorithm 1 的 SETUP / QUERY / ANSWER 与 Algorithm 2 的骨架，我们逐行对上了。**
BFF（`k=3`）、表构造 `P_{c,b}`、索引分解 `(r_a, c_a)`、one-hot 列选择、`BlindRotate`、
`SampleExtract_0`、三路相加 —— 这些**没有抄错**。

**但「符合论文算法」这个问题的答案是：不符合，差三块，另有五处偏离。**

| 缺口 | 性质 | 影响 |
|---|---|---|
| **D1** 查询未加密 | 安全 | 协议有明文信道，D.2 论证不成立 |
| **D2** 加密打分缺失 | **算法核心** | CAPE 相对 FusePIR 的**唯一增量**没做；安全 + 口径都受影响 |
| **D3** 行选择子非真 LWE | 安全 | 既有 P0-1 |
| D4 `d` 语义 | 参数保真 | 不查错，但耦合不清 |
| D5a/b/c | 有意偏离 | 功能等价；D5c 直接影响 `B_pay` 与可比性 |

**⇒ 准确的说法是：我们实现的是「FusePIR.Answer（候选检索）+ 明文化的 Bloom 合取判定」，
不是 CAPE。** 把它说成 CAPE 复现是**过度声明**。

### 顺带得到两个对之前结论的修正

1. **性能口径**：我们的 102 s **不含** D2 那 80 次 `CtCtMul` + 旋转。
   ⇒ 之前「同模型我们只差 1.31×」的说法**建立在省略 D2 的实现上**，必须加这条注。
   补上 D2 会让基线**更慢**（量级估 +5%，见 `达到论文CAPE速度…md` §1.3 的旧估算）。
2. **`h_a` 退化 + D1 明文关键词**叠加后，**关键词之间的关联性完全暴露**；
   这不是"演示简化"能一笔带过的，任何对外说明都得写明。
