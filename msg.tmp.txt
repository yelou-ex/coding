fix(route-A): native 线彻底走通 —— 三规模 4/4 PASS

修掉两个真实 bug：

1) gadget 溢出（这个是「测试 1 精确匹配」抓到的）
   gadget g_i = base^i 存在 unsigned __int128 里，而 base^8 = 2^128 就溢出，
   于是 levels > 8 时所有 i >= 8 的 gadget 被算成 0，那些 RGSW 行退化成 Enc(0)。
   后果：N=8192（levels 11）与 N=16384（levels 25）上「RGSW(1) 乘 ct = ct」全错，
   而 N=4096（levels 5）正常 —— 正是「小参数巧合能过、真实参数才炸」的又一例。
   修法：g_i 只需要 mod q_j，改成逐素数做模幂，不再构造全宽值。

   ⚠️ 值得记：同一批 bug 下，测试 3（只检查「one-hot 进 one-hot 出」这种结构性质）
   在 N=8192/16384 上**照样 PASS**，只有测试 1（逐系数精确匹配）抓到了它。
   弱断言会漏掉真实的算法错误。

2) 序列化路径不可靠
   Ciphertext::load 在这个 MinGW 构建下抛 index must be within [0, size)；
   用逐段标签把 external_product / from_ntt / decrypt / 密钥句柄检查全部排除后，
   只剩它。改用 native 侧密文句柄表（Ciphertext 留在 C++ 内存里）——
   这本来也是接 CAPE 该有的形态：服务端状态留在 native，只让查询/响应跨边界。
   save 本身可用，load 不可靠，真做跨网络还得另想办法。
