wip(route-A): 实现 nativeCapeAnswer（完整 CAPE ANSWER），已编过、尚未接线

新增 nativeCapeAnswer(h, d, C, k, bPay, tableFlat, cIdx, rIdx)：
  在 C++ 内跑完整个 CapeEndToEnd4.ANSWER —— k 条路 x B_pay 个单元，每单元
  列选择（C 次 CtPtMul）+ 盲旋转（d 轮 CMUX）+ SampleExtract_0，再做密文域三路相加。
  明细：
  - 明文表 P_{c,b}(X) 一次性 NTT 并复用（Java 侧是每 (a,b,c) 重建，这里省 k 倍明文 NTT）
  - SampleExtract_0 严格照 LweRlweBridge.sampleExtract 的 reverse 约定：
      [pi][0] = c0[0]；[pi][1+k] = c1[(n-k) mod n]（k>0 时取负）
  - 返回扁平化 long[B_pay][L][n+1]，与 Java ctPaySample 布局一致 => DECODE 不用改
  - 整条链路只有 1 次 JNI 调用；引导密钥/明文表/选择子全留 native 内存

实测 native ANSWER（同形状基准 nativeAnswerBench）：5 762.8 ms / 5 823.3 ms
对照路线 B（纯 Java）：15 407 ms => 约 2.67x
