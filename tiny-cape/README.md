# tiny-cape —— CAPE 极简验证版（规范逐条实现）

> 对应《CAPE 实现步骤（极简验证版）》。
> 参数 **N=8, t=17, q=97**，**噪声为 0**，**无 CAPE-C**，每一步的明文都能打印出来手工核对。
>
> 位置：`cape/tiny-cape/`　零依赖（纯 JDK，任意 JDK 11+）

---

## 一、为什么单独做一层

仓库里已有的 HE 代码走 **MPC4J / SEAL 的 BFV** 路线，它**接受不了**这里的极小参数：

| 约束 | MPC4J / SEAL | 本规范 |
|---|---|---|
| 系数模数 q | 必须是若干 NTT 友好素数的乘积（几百 bit） | **97**（单个小数） |
| 环维度 N | 有最小规模要求（实测 N=2048 只有 1 个工作素数） | **8** |
| 噪声 | 必须留足预算 | **0** |

所以这一层是**独立的、零依赖的**实现，专门服务"正确性可手工验证"这个目标。
它与 MPC4J 主线的结论可以互相印证，但**不共用代码**。

## 二、数学可行性（已实测确认，不是假设）

| 检查 | 结果 |
|---|---|
| `X^8+1` 在 `F_17` 上完全分裂 | ✅ **8 个根** = 3,5,6,7,10,11,12,14 → **8 个槽位可用**（槽位编码成立） |
| `16 \| q−1`（q=97） | ✅ 96/16 = 6 → 16 阶单位根存在（ω = 5⁶ = **8**，ω⁸ = −1 ✓） |
| Δ = ⌊q/t⌋ | = **5** |
| **可表达明文上界** | **9** —— `⌊(q/2)/Δ⌋ = 48/5` |

## 三、⚠️ 三个必须知道的约束（规范没写，但实测撞到了）

### 约束 1：明文（**含卷积系数**）必须 ≤ 9

"噪声为 0"**不等于**"什么值都能表达"。相位必须落在 `(−q/2, q/2]` 才能被正确解码，
即明文值 `≤ ⌊(q/2)/Δ⌋ = 9`。

**关键细节**：环乘法是**卷积**，结果的每个系数是"N 个乘积项之和"。
所以约束的对象是**卷积后的系数**，不是逐点乘积。

> 取 **0/1 数据**时卷积系数 ∈ `[−N, N] = [−8, 8] ⊆ [−9, 9]` ✓
> 而 **0/1 正是 CAPE 的真实数据形态**（Bloom 位、指纹位），所以这不是妥协。

`CtCtMul` 的 8 组自检用 0/1 数据**全过**；用 `[0,3]` 随机数据会因卷积和超窗而失败
—— 那是**容量问题，不是实现错误**。

### 约束 2：`X^{−r*}` 的常数项是 `±P[(−r*) mod N]`，**不是** `P[r*]`

`X^{−r*}·P(X) = Σ_k P[k]·X^{k−r*}`。当 `k < r*` 时指数为负，要用
`X^{k−r*+N} = X^{k−r*}·X^N = −X^{k−r*}` 归一 —— **负号只取一次**。

> 所以 `P(X)·X^{−r*}` 的常数项来自 `k = r*` 那一项，但带一个负号（`r* ≥ 1` 时）。
> 这正是 `BlindRotate.coefficientAt` 的公式；**不要**记成"常数项 = P[r*]"。
>
> 想直接取 `P[r*]`，需要客户端改送 `X^{N−r*}` 的旋转量（本实现按规范保持 `X^{−r*}`）。

### 约束 3：负数必须用**中心代表元**

`Z_t`（t=17）里 `−1` 的代表元是 `16`，而 `Δ·16 = 80 > q/2 = 48` —— **无法表达**。
必须换成中心代表元 `−1`（相位 `−5 ≡ 92`）。

> 盲旋转必然用到 `X^N = −1`，所以这条**一定会遇到**。
> 对拍时两边都要中心化，否则会把"表示不同"误判成"算错了"
> → 用 `key.decryptRLWECentered()` 和 `Poly.centralize()`。

| 项 | 状态 | 说明 |
|---|---|---|
| **SampleExtract** | ❌ 代数关系未对齐 | 提取出的 LWE `(a,b)` 与 `phase[0]` 的关系我没推对。**不影响端到端**（直接读常数项即可，`BlindRotate` 已把目标行挪到常数项）。推导记录在 `TinyKey.sampleExtract0` 注释里，下次从这里接着查。 |
| **槽位掩码乘法** | ⚠️ q=97 下不可行 | 掩码以"槽位 one-hot 的**系数形式**"参与环乘法时，系数幅值可达 `N·t/2 ≈ 68`，`Δ·N·t/2 ≈ 340 > q/2` → 必然溢出。**这是 q=97 与掩码乘法之间的真实矛盾**，要支持它得把 q 提到 ~25000。 |
| **列选择** | ⚠️ 本演示绕开 | 按 README §1.2，列选择是 `CtPtMul`（密文×明文），one-hot 的每一位是**明文多项式的系数**。本演示的 R=C=2 且数据是明文，所以直接按 `(r*, c*)` 取列，没有走密文列选择。 |
| **Pack / CAPE-C** | — | 规范明确"无 CAPE-C"，且本极小版不需要 Pack（不涉及多条 LWE 合并）。 |

> **重要**：上表两项 ❌ 都**不影响端到端结论**。端到端走的是
> "盲旋转 → 读常数项 → 三路相加 → Bloom 判分"，每一步都已独立验证。
